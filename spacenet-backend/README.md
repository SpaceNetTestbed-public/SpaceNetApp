# SpaceNet Backend
Used to easily interface with the dynamic topology generator and constellation simulator by providing endpoints that manage configurations and run tasks.

## Prerequisites
* Python 3.9.5
* Redis Server 

## Folder setup
The constellation simulator and dynamic topology generator should already be a submodule and the configuration can be edited in `.gitmodules`

When the branch name is changed or any changes were made to the remote repositories, do the following command
```
git submodule update --remote --init --recursive
```

## Setting up a Python Virtual Environment
With Python installed it is recommended to use a virtual environment for installing libraries in the base folder. 

```
python3 -m venv env
```

To activate the virtual environment, do the following:

```
source ./env/bin/activate
```

Once activated, you need to install the corresponding libraries found in the spacenet-backend folder called `requirements.txt`. Do the following command.

```
pip3 install -r requirements.txt
```

If needed, to get out of the virtual environment, do:
```
deactivate
```

## Running the Backend
After everything is set up, open up two terminals and do the following commands in seperate termials in the `spacenet-backend` folder:

```
sudo ../env/bin/rq worker default
sudo ../env/bin/rq worker plot
sudo ../env/bin/python3 run.py
```
The reason sudo is needed is because the constellation simulator needs sudo access to run certain scripts.

If you want to view the available routes, you can go to `localhost:5000/apidocs` where you can see Swagger documentation listing routes and you are able to do testing on them. The API has no built-in authentication and is intended for local or trusted-network use only. Setting `ENABLE_TUNNEL=1` when using `run-dev.sh` or `run-prod.sh` exposes it to the public internet at your own risk.

### Scripts
The `run-dev.sh` is a script for running all the workers together so you don't have to open new terminals

The `run-prod.sh` is a script for production facing code once the app is ready for the public

## Developing
The routes folder has most of the functionality of the backend organized by these files. Feel free to add more routes in `__init__.py` or add on top of these files. 

| Route  | Description |
| ------------- | ------------- |
| configurations.py | Manage your configurations for the dynamic topology generator and constellation simulator |
| data.py | Mainly TLE data |
| experiments.py | Where users can create and edit experiments and other functionalities |
| gif.py | Manages gifs/plots and configurations. |
| gs.py | Manages ground station files |
| jobs.py | Where users queue different tasks including: dynamic topology generation, constellation simulation, and gif/plot generation |
| logs.py | Where users can view their logs of previous ran tasks in jobs |
| outputs.py | Where users can download their outputs generated by the jobs |
| users.py | User management and configuration |

For a temporary public url install cloudflared and use the following command after the application is running

```
cloudflared tunnel run --url http://localhost:5000
```
